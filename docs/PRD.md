## 二、产品概述

### 2.1 产品定位

DeepService 是一款**面向中小企业的 AI 智能客服中台**，基于 DeepSeek 大语言模型和 RAG（检索增强生成）技术，以 SaaS 形态提供开箱即用的智能客服能力。核心差异化在于**四层 AI 幻觉防御体系**——让 AI 客服"不知道就说不知道"，从根本上解决大模型胡说八道的问题。

### 2.2 核心价值主张

| 痛点 | 传统方案 | DeepService 方案 |
|------|----------|-----------------|
| AI 编造虚假信息 | 无有效控制手段 | **四层幻觉防御**：知识边界 + RAG + 验证 + 兜底 |
| 对话上下文丢失 | 单轮问答 | **多轮记忆**：滑动窗口 + 摘要压缩 + 实体追踪 |
| 知识库更新困难 | 需要重新训练模型 | **文档即服务**：上传 Markdown/PDF 自动索引 |
| 无法转人工 | 死循环 | **六维度触发**：智能判断何时转接人工坐席 |
| 客服质量无法度量 | 无监控 | **置信度评分 + 满意度追踪 + 管理后台** |

### 2.3 适用场景

**场景 A：电商售后客服**（主打场景）

| 维度 | 详情 |
|------|------|
| 典型用户 | 淘宝/京东/拼多多卖家、独立站电商 |
| 核心需求 | 7×24 小时自动回复退换货、物流、产品咨询 |
| 业务特征 | 问题重复度高（80%是 FAQ）、季节性峰值（双11） |
| 预期效果 | 自动解决率 >70%，转人工率 <15% |

**场景 B：SaaS 产品技术支持**

| 维度 | 详情 |
|------|------|
| 典型用户 | SaaS 创业公司、软件服务商 |
| 核心需求 | 产品使用指南、Bug 排查、账号问题 |
| 业务特征 | 问题专业性强、版本迭代快、知识库频繁更新 |
| 预期效果 | 文档驱动的精准回答，降低人工支持成本 60% |

### 4.2 功能详细说明

#### 交互层

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 实时对话 | SSE 流式输出，打字机效果，支持 Markdown 渲染 | P0 |
| 会话管理 | 新建/切换/删除会话，会话列表持久化 | P0 |
| 满意度评价 | 每条AI回复支持好评/差评，附带原因 | P1 |
| 附件上传 | 支持上传图片（如商品照片）辅助问题描述 | P2 |
| 语音输入 | 移动端支持语音转文字 | P3 |
| 快捷回复 | 常见问题一键点击（如"查订单""退换货"） | P1 |

#### 核心能力层

| 功能 | 描述 | 优先级 |
|------|------|--------|
| **RAG 检索生成** | 混合检索（语义 + 关键词）+ 重排序 + LLM 生成 | P0 |
| **多轮对话记忆** | 滑动窗口 + 摘要压缩 + 跨轮次实体追踪 | P0 |
| **意图识别** | 规则 + LLM 双层策略，支持多意图拆分 | P0 |
| **知识边界控制** | 检索相似度低于阈值时拒答，而非编造 | P0 |
| **人工转接** | 六维度触发 + 上下文打包透传 | P1 |
| **结构化流程** | 退换货等场景的 FSM + 槽位填充 | P1 |
| **多语言支持** | 优先中文，预留英文/日文接口 | P2 |

#### 管理监控层

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 仪表盘 | 活跃会话数、平均置信度、转人工率、热门问题 | P1 |
| 对话日志 | 按时间/意图/用户搜索，支持对话回放 | P1 |
| 知识库管理 | 文档 CRUD、批量导入、重建索引、检索测试 | P1 |
| 数据分析 | 意图分布趋势、满意度变化、峰值时段分析 | P2 |
| 成本追踪 | LLM API 调用次数和费用统计 | P2 |

## 五、非功能性需求

### 5.1 性能要求

| 指标 | 目标值 | 测量方式 |
|------|--------|----------|
| 首Token延迟 | < 2s | 从用户发送到首个 Token 返回 |
| 流式输出速率 | > 30 tokens/s | 每秒生成的 Token 数 |
| 并发会话数 | > 1000 | 同时活跃的会话数 |
| 知识库检索延迟 | < 500ms | 从查询到返回 Top-5 结果 |
| API 可用性 | > 99.5% | 月度统计 |

### 5.2 安全要求

| 要求 | 实现方案 |
|------|----------|
| API Key 安全 | 环境变量存储，不硬编码，HTTPS 传输 |
| 用户数据隔离 | 会话级别隔离，用户只能访问自己的会话 |
| 输入安全过滤 | 敏感词检测、Prompt 注入检测、长度限制 |
| 输出内容审核 | 敏感内容后置过滤 |
| 日志脱敏 | 手机号、邮箱等在日志中自动脱敏 |

### 5.3 可扩展性

| 维度 | 设计 |
|------|------|
| 模型可替换 | LLM 调用统一封装，切换模型只需修改配置 |
| 知识库可扩展 | 支持多种文档格式，增量索引 |
| 渠道可扩展 | 统一 API 接口，Web/移动端/微信/钉钉均可接入 |
| 多租户 | 预留 tenant_id 字段，支持 SaaS 化 |

### 5.4 可用性 (SLA)

| 指标 | 目标 |
|------|------|
| 服务可用性 | 99.5%（月度） |
| P99 响应延迟 | < 10s |
| 故障恢复时间 | < 30 分钟 |
| 数据持久性 | 99.9%（依赖 PostgreSQL） |

## 六、产品路线图

### V1.0 — MVP（当前版本，2-3周）

- ✅ 核心对话功能（流式输出、Markdown 渲染）
- ✅ RAG 检索增强（混合检索 + 来源标注）
- ✅ 四层幻觉防御体系
- ✅ 多轮对话记忆
- ✅ 意图识别（规则 + LLM 双层）
- ✅ Web 聊天界面（响应式）
- ✅ 管理后台基础版
- ✅ API 接口（REST + SSE）

### V2.0 — 增强版（1-2月后）

- [ ] 多知识库隔离（不同产品线独立知识库）
- [ ] 数据分析与报表导出
- [ ] 坐席工作台（人工客服界面）
- [ ] WebSocket 实时消息
- [ ] 邮件/短信通知
- [ ] 第三方平台接入（企业微信、钉钉、飞书）

- [ ] 多租户 SaaS 架构
- [ ] 用量计费系统
- [ ] 自定义模型微调

- [ ] 智能质检（自动评估客服质量）
- [ ] 多语言国际化（英语、日语）
